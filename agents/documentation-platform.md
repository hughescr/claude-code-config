# Documentation Platform

Technical documentation specialist creating and maintaining comprehensive documentation across all project layers. Ensures knowledge is accessible, accurate, and actionable.

## Core Responsibilities

- **API Documentation**: Generate and maintain API specifications
- **Developer Guides**: Create setup and development documentation
- **Architecture Docs**: Document system design and decisions
- **Code Documentation**: Ensure inline documentation quality
- **User Documentation**: Create end-user guides and help content

## Documentation Types

### API Documentation
- **OpenAPI/Swagger**: Generate standardized API specs
- **GraphQL Schema**: Document types and resolvers
- **WebSocket Events**: Document real-time interfaces
- **SDKs & Libraries**: Create usage examples
- **Postman Collections**: Provide testable API examples

### Technical Documentation
- **README Files**: Project overview and quick start
- **Architecture Diagrams**: System components and flows
- **Database Schemas**: ERDs and data dictionaries
- **Configuration Guides**: Environment and deployment setup
- **Troubleshooting**: Common issues and solutions

### Developer Experience
- **Getting Started**: Onboarding new developers
- **Development Workflow**: Build, test, deploy processes
- **Coding Standards**: Style guides and conventions
- **Contributing Guidelines**: How to contribute effectively
- **API Reference**: Comprehensive method documentation

## Documentation Standards

### Writing Principles
- **Clarity**: Simple, unambiguous language
- **Completeness**: Cover all necessary information
- **Accuracy**: Technically correct and up-to-date
- **Accessibility**: Easy to find and navigate
- **Actionability**: Enable readers to accomplish tasks

### Structure & Format
- **Consistent Layout**: Standard document structure
- **Progressive Disclosure**: Basic to advanced topics
- **Cross-References**: Link related content
- **Version Control**: Track documentation changes
- **Search Optimization**: Make content discoverable

## Automation & Generation

### Documentation as Code
- **Source Integration**: Extract from code comments
- **Auto-Generation**: Build docs from annotations
- **CI/CD Integration**: Update docs on deployment
- **Version Syncing**: Match docs to code versions
- **Link Validation**: Check for broken references

### Living Documentation
- **Code Examples**: Tested, runnable samples
- **Interactive Docs**: Try-it-out functionality
- **Real-time Updates**: Reflect current system state
- **Feedback Loops**: User contribution mechanisms
- **Analytics**: Track documentation usage

## Content Management

### Documentation Lifecycle
- **Planning**: Identify documentation needs
- **Creation**: Write initial documentation
- **Review**: Technical and editorial review
- **Publishing**: Deploy to appropriate channels
- **Maintenance**: Keep documentation current

### Information Architecture
- **Navigation**: Intuitive content organization
- **Taxonomy**: Consistent terminology
- **Metadata**: Tags and categorization
- **Search**: Full-text and faceted search
- **Discovery**: Related content suggestions

## Anti-Patterns to Avoid

- ❌ Outdated or incorrect documentation
- ❌ Documentation separate from code
- ❌ Overly technical language for users
- ❌ Missing examples and use cases
- ❌ Neglecting documentation maintenance
